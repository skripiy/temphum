# Архитектура temphum

Документ заменяет прежнее ТЗ (`tz.md`) и служит контекстом для дальнейшей разработки, в том числе с ИИ-ассистентами.

## Принципы

- **100 % serverless и бесплатно.** Никаких своих серверов (Express, FastAPI, VPS). Всё на Cloudflare Free.
- **Один провайдер на бэкенд, базу, планировщик и фронтенд:** Worker + D1 + Cron Triggers + Static Assets.
- **Плата не зависит от облака в момент замера:** замеры копятся в буфере и досылаются.
- **Лимиты бесплатного плана учтены в дизайне.** Запись пачками, чтение по первичному ключу, инкрементальная дозагрузка графиков, агрегация и чистка по cron.

## Компоненты

1. **IoT-узел** — ESP32, 1–3 датчика (AM2301/DHT21, DHT22, DHT11, BME280).
   - Режимы: постоянное питание или deep sleep.
   - Каждый датчик шлёт данные с собственным токеном: `POST /api/ingest`, пачки до 100 замеров.
   - Время — по NTP, в UTC.
2. **Cloudflare Worker** (`worker/src/index.js`):
   - приём данных с проверкой токена (в базе хранится только SHA-256) и валидацией диапазонов;
   - API для дашборда, защищённое `READ_KEY`;
   - cron-задачи.
3. **D1 (SQLite):**
   - `devices` — датчики, последнее значение, интервал отправки, признак «улица»;
   - `readings_raw` — сырые замеры, хранятся `RAW_RETENTION_DAYS` (30);
   - `readings_hourly` — почасовые агрегаты, хранятся `HOURLY_RETENTION_DAYS` (400);
   - `readings_daily` — суточные агрегаты по локальному `TZ`, хранятся всегда.
   - Таблицы замеров — `WITHOUT ROWID` с PK `(device_id, ts)`. Схема меняется только новыми файлами в `worker/migrations/`.
4. **Дашборд** (`worker/public/`): статика, uPlot, PWA, режим `?kiosk=1`.
   - Погода (Open-Meteo) запрашивается браузером напрямую по координатам `SITE_LAT`/`SITE_LON` из `/api/devices`.

## История

Первая версия (апрель 2026) была рассчитана на MongoDB Atlas Data API + Atlas Scheduled Trigger + Next.js на Vercel. Atlas Data API и HTTPS Endpoints MongoDB отключила 30.09.2025, поэтому прошивка больше не могла писать в базу напрямую. Из неё перенесены:

- **Deep sleep** — батарейный режим узла.
- **Метка времени на сервере** — если устройство не прислало `ts`, его ставит сервер (в Mongo это было время из `_id`).
- **BME280** — в ТЗ была заявлена поддержка; теперь он полноценно поддерживается вместе с давлением.
- **Суточный архив min/avg/max** — теперь считается cron-задачей Worker, а не Atlas Function, и дополнен почасовым уровнем.
- **TTL для сырых данных** — заменён ежедневной чисткой в cron.
